# VSCode SVG 扩展 — 需求规格说明书（PRD / SRS）

## 1. 项目概述

### 1.1 目标
开发一个基于 TypeScript 的轻量级 VSCode 扩展，为工作区中的 `.svg` 文件提供两项原生视图增强能力：
1. **Explorer 文件标记**：在资源管理器中直观标识 `.svg` 文件，使其与普通文本文件和目录区分开来。
2. **Outline 元素大纲**：打开 `.svg` 文本文件时，在 VSCode 原生 Outline（大纲）视图中展示 SVG 元素的嵌套层级结构，并支持点击跳转源码与编辑实时刷新。

### 1.2 范围界定

| 类别 | 包含内容（In Scope） | 不包含内容（Out of Scope） |
| :--- | :--- | :--- |
| **资源管理器** | 对 `.svg` 普通文件附加 `[]` 界面标记与悬停提示 | 修改文件名/文件内容、自定义文件图标主题、文件夹聚合角标 |
| **大纲视图** | 展示所有 SVG/XML 元素嵌套层级、按 `标签名#id` 或 `标签名` 命名、点击跳转源码、编辑自动更新、不完整 XML 容错不崩溃 | 完整 SVG 1.1/2.0 规范校验、图形可视化预览、代码补全/悬停文档/格式化/重命名 |
| **工程交付** | 扩展源码、自动化单元测试、示例 `.svg` 文件、安装启动指南、真实运行截图 | Phase 1 CLI 代码复用分析（后续阶段按需补充） |

---

## 2. 基线行为对照（原生 VSCode 现状）

在未安装本扩展（且未安装其他第三方 XML/SVG 语言插件）的纯净 VSCode 环境中：
- **Explorer 视图**：`.svg` 文件与普通 `.txt`、`.md` 文件无明显文字标记区分，右侧无附加 badge。
- **Outline 视图**：打开 `.svg` 文件时，VSCode 默认以内置 `xml` 语言高亮，但原生不提供 XML/SVG 符号解析，Outline 面板显示 `No symbols found in document '<filename>.svg'`。

安装并启用本扩展后，上述两处视图均由本扩展提供增强能力。

## 3. 功能需求详述

### 3.1 FR-1：SVG 文件标记（Explorer Decoration）

#### 3.1.1 核心行为
- 在 VSCode 左侧 **Explorer（资源管理器）** 视图中，所有 `.svg` 文件条目右侧显示 `[]` 标记。
- 悬停在该文件条目/标记上时，显示清晰提示文本（如 `SVG file`）。
- 标记纯属界面附加装饰信息，**绝不修改磁盘上的文件名、路径或文件内容**。

#### 3.1.2 激活时机
- 用户打开包含 `.svg` 文件的工作区时，即使**尚未在编辑器中打开任何 `.svg` 文件**，Explorer 中的 `.svg` 文件也必须自动显示 `[]` 标记。
- 工作区打开后，新创建或重命名为 `.svg` 的文件应能显示 `[]`；将 `.svg` 重命名为非 `.svg` 后，标记应消失。

#### 3.1.3 目标过滤判定表（边界条件）

| 资源示例 | 文件系统类型 | 是否显示 `[]` | 说明 |
| :--- | :--- | :---: | :--- |
| `example.svg` | 普通文件 | **是** | 标准 `.svg` 文件 |
| `LOGO.SVG` / `Icon.Svg` | 普通文件 | **是** | 后缀匹配**大小写不敏感** |
| `sub/dir/flow.svg` | 普通文件 | **是** | 任意子目录下的 `.svg` 文件 |
| `notes.txt` / `data.xml` / `svg` | 普通文件 | **否** | 非 `.svg` 后缀文件 |
| `demo.svg.bak` / `demo.svg.json` | 普通文件 | **否** | 仅中间包含 `.svg`，最终扩展名非 `.svg` |
| `.svg` | 隐藏文件（无主文件名） | **否** | 仅点开头的隐藏文件名不视为有效 `.svg` 扩展名（见待确认项） |
| `assets/` | 目录 | **否** | 普通目录不加标记 |
| `icons.svg/` | 目录 | **否** | **即使目录名以 `.svg` 结尾，也不得加标记** |
| `link.svg` → 指向普通文件 | 符号链接（文件） | **是** | 底层目标为文件而非目录时显示 `[]` |
| `dirlink.svg` → 指向目录 | 符号链接（目录） | **否** | 底层目标为目录时不加标记 |
| 无权限或已被删除的 URI | 读取失败 | **否** | 静默返回无装饰，不得抛错或弹窗 |

### 3.2 FR-2：SVG 元素大纲与源码定位（Outline View）

#### 3.2.1 适用文件匹配
- 编辑器打开任意路径以 `.svg`（大小写不敏感）结尾的文本文件时，本扩展的大纲能力生效。
- 无论 VSCode 当前将该文件识别为 `xml`、`svg` 还是其他文本语言模式，均应正常触发大纲解析。

#### 3.2.2 嵌套层级展示
- 在 VSCode 原生 **Outline（大纲）** 视图中展示 SVG 文档的完整元素嵌套树：
  - 根元素（如 `<svg>`）；
  - 容器元素（如 `<g>`、`<defs>`、`<symbol>`、`<clipPath>`、`<mask>` 或任意包含子元素的标签）；
  - 叶子元素（如 `<rect>`、`<circle>`、`<line>`、`<ellipse>`、`<polygon>`、`<path>`、`<text>` 等自闭合标签或无子元素的成对标签）。
- 支持任意深度的嵌套分组与同级多兄弟节点，大纲中节点的排列顺序必须与源码中出现的先后顺序严格一致。

#### 3.2.3 节点显示名称规范

| 源码示例 | 大纲节点显示文本 | 规则说明 |
| :--- | :--- | :--- |
| `<svg id="canvas" width="800">` | `svg#canvas` | 有非空 `id` 时显示 `标签名#id` |
| `<rect id="start" x="10" y="20"/>` | `rect#start` | 自闭合标签同样遵循 `标签名#id` |
| `<g id='layer-1'>` | `g#layer-1` | 同时支持单引号与双引号属性值 |
| `<rect id = "box1" />` | `rect#box1` | 支持 `=` 两侧存在空白字符 |
| `<text x="10" y="20">Hello</text>` | `text` | 无 `id` 属性时仅显示标签名 |
| `<circle id="" r="5"/>` | `circle` | `id` 为空字符串或仅含空白时，按无 `id` 处理 |
| `<svg:rect id="r1"/>` | `svg:rect#r1` | 带命名空间前缀的标签保留完整标签名 |

> [!NOTE]
> 不要求在大纲节点上展示额外属性（如 `x`、`y`、`fill` 等），保持与原生简洁风格一致；不同类型元素可按容器/图形/文本映射区分度良好的原生 `SymbolKind` 图标。

#### 3.2.4 源码定位与跟随
- **点击跳转**：点击 Outline 视图中任意节点时，编辑器自动滚动并将光标/选区精准定位到该元素在源码中的**开始标签（标签名）位置**。
- **范围覆盖**：每个大纲节点的 `range` 覆盖从开始标签 `<` 到对应结束标签 `>`（或自闭合 `/>`）的完整源码区域；`selectionRange` 严格位于 `range` 内部，确保 VSCode 原生“Follow Cursor（光标跟随高亮大纲节点）”正常工作。

#### 3.2.5 编辑实时刷新
- 用户在编辑器中直接修改 `.svg` 内容（新增元素、删除元素、修改 `id`、调整父子嵌套、改变缩进/行号）时，无需保存文件或手动刷新，Outline 视图应自动更新并反映最新结构与行号。

#### 3.2.6 语法兼容与特殊结构处理
大纲解析器须正确处理常见真实 SVG/XML 语法，不发生误解析：
1. **忽略非元素声明**：`<?xml version="1.0" encoding="UTF-8"?>`、`<!DOCTYPE svg ...>`、HTML/XML 注释 `<!-- <rect id="fake"/> -->`、`<![CDATA[ <rect/> ]]>` 中的内容均不得作为大纲节点出现。
2. **多行标签与特殊属性值**：
   - 开始标签属性跨多行换行时，能正确提取 `id` 并计算准确起止位置；
   - 属性值内部包含 `>`、`/`、`<` 字符（例如 `xmlns="http://www.w3.org/2000/svg"`、`data-expr="a > b"`）时，不得误判标签提前结束或误判为自闭合。
3. **元素内普通文本**：`<text>开始节点</text>` 中的纯文本内容不生成独立大纲节点，不影响父元素的范围闭合。

#### 3.2.7 不完整 / 非法 XML 容错要求（核心稳定性要求）
编辑过程中文档经常处于临时不合法状态，本扩展必须满足：
1. 以下任一异常输入下，**允许清空大纲（返回空数组 `[]`）**，但**绝不允许抛出未捕获异常、弹出错误提示框、卡死编辑器或导致扩展崩溃**：
   - 空文件或纯空白文件；
   - 输入半个开始标签（如 `<rec`、`<rect id="a`）；
   - 属性值引号未闭合（如 `<rect id="unclosed/>`）；
   - 开始标签未闭合（缺少 `</g>` 或 `</svg>`）；
   - 开始与结束标签不匹配（如 `<g><rect></g>`）；
   - 出现多余的孤立结束标签（如 `</svg>`）；
   - 注释或 CDATA 未闭合（如 `<!-- todo`）。
2. 当用户将上述残缺内容补全为合法 XML 后，大纲必须在下一次编辑刷新时自动恢复显示完整层级。

## 4. 非功能需求（NFR）

| 维度 | 具体要求 |
| :--- | :--- |
| **性能** | ① Explorer 文件装饰对非 `.svg` 文件仅做内存字符串后缀判断，**零磁盘 I/O**；<br>② 1000 行级 SVG 文档大纲解析耗时 < 20ms；<br>③ 正确响应 VSCode `CancellationToken`，快速连续输入时可中止过期请求。 |
| **稳定性与无副作用** | 所有外部交互（文件 `stat`、文本解析）均具备异常兜底；扩展停用时通过 `context.subscriptions` 完整释放所有 `Disposable`，无资源泄漏。 |
| **技术规范** | 使用 TypeScript 严格模式（`strict: true`）与面向对象设计；仅使用 VSCode 稳定版官方 API，**不引入重型第三方运行时依赖**。 |
| **可测试性** | SVG 解析逻辑与文件过滤规则与 `vscode` 运行时模块解耦，支持脱离 VSCode 界面独立运行自动化单元测试。 |

## 6. 已确认设计决策（定稿）

以下边界细节已评审确认并作为最终实现依据：
1. **隐藏文件 `.svg`（无主文件名）**：按 POSIX / `path.extname('.svg') === ''` 语义，**不显示** `[]` 标记。
2. **多根节点 SVG 片段**：只要文档内所有标签配对完整、语法无残缺，**允许展示多个顶层节点**；仅在存在未闭合、错配或残缺语法时清空大纲。
3. **未保存的新建无标题文件（`Untitled-1`）**：**仅匹配带 `.svg` 路径的文件**（`**/*.svg` / `**/*.SVG`），不匹配无路径的 `untitled` 文档，避免误伤普通 XML 文件。
4. **工程技术栈与仓库位置**：独立仓库位于 `/Users/lazy/svg-vscode-extension`，采用 `TypeScript (tsc)` 编译与 `Vitest` 单元测试。
